## Final Oracle audit

`database/step6a_verify.sql` is a read-only SQL*Plus audit. Its SVR_APP/XEPDB1 run reached and passed the eight-table/constraint/orphan/charge assertions, object validity/compilation checks, disposable-ID checks and the first four seed comparisons. It then stopped on an ORA-00918 in the generated VEHICLE comparison; the complete partial output is preserved as `evidence/step6a-final-oracle-audit-partial.log`. The generator was corrected to give every expected CTE column a distinct alias. A fresh password-free **SYS OS-authenticated** read-only session switched to XEPDB1, set `CURRENT_SCHEMA=SVR_APP`, and executed the corrected two-way comparison for all 81 original seed literals (`evidence/step6a-seed-diff-sys.log`). Both `missing_or_changed` and `unexpected_or_changed` are **zero for every one of the eight tables**. The comparison was repeated after the last disposable customer update/delete; `step6a-seed-diff-sys.log` is that final run and the earlier run is retained as `step6a-seed-diff-sys-before-customer-update.log`. The comparison account is identified accurately in its log; the first-phase checks ran as SVR_APP.

Final counts in the SVR_APP phase: CUSTOMER 10, CUSTOMER_PHONE 11, VEHICLE_TYPE 10, BRANCH 10, VEHICLE 10, EMPLOYEE 10, RENTAL 10, PAYMENT 10. All 8 primary, 8 foreign, 8 unique and 54 check constraints were enabled and validated. All five orphan categories, charge/availability mismatches, overpayments and cancelled/pre-start payment conflicts were zero. `USER_OBJECTS` had no invalid entries and `USER_ERRORS` no rows; package, package body, two sequences and three triggers were VALID. All seven disposable-ID/history checks returned zero. The first phase's ORA-00918 was a comparison-query defect, not an Oracle data or compilation error.

After customer 1989 was deleted and the controlled stalled-write test for customer 1990 completed, a final read-only count/metadata check (`evidence/step6a-post-cleanup-sys.log`) again showed 10/11/10/10/10/10/10/10 rows, zero test customer/type/branch/vehicle/employee/rental/payment IDs (including 1990), zero invalid objects or compiler errors, and the same 78 enabled, validated constraints. Together with the final 81-row two-way equality check, this confirms the original seed and structural consistency at Step 6A closure. Only the normal port 8080 server remains running; temporary ports 8081 and 8082 were stopped.

No committed workflow history was created during the browser rehearsal. The rollback-only server was used for rental/return/payment operations; disposable master records were removed through the browser. Oracle sequences can have gaps after rolled-back tests.
