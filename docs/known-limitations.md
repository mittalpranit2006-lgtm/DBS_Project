# Known limitations after Step 6A

- **Cycle VI:** G1 p. 2 requests Cycle Sheets I–VI queries and outputs. No readable, explicitly labelled Cycle VI sheet was supplied. Existing Oracle project demonstrations do not establish full Cycle VI coverage. See `lab-cycle-map.md`.
- **Review 1 diagram:** R1 pp. 3, 6–7 show nine relations, including `RENTAL_STATUS`. The authorized implementation has eight tables and a checked `RENTAL.Status_Name`; the submitted Review 1 diagram still needs an amendment or faculty acceptance. See `design-changes.md` and `er-implementation.mmd`.
- **Cancellation and refunds:** The database permits a narrow rolled-back academic Cancelled-rental DML example, and the schema records payment statuses, but the API/UI do not implement a genuine cancellation or refund/reversal workflow. Neither guideline explicitly requires these operations; they are scope limitations of the selected rental domain, not completed features. Never describe a status value alone as an operational cancellation/refund feature.
- **Login and authorization:** The localhost app has no user login or application-level permission enforcement. `EMPLOYEE.Role` describes a duty, not access. The supplied G1/G2/R1 source review found no explicit login policy; this is a documented scope limitation. Run only on trusted localhost. Oracle account privileges and local binding do not amount to per-user app authorization.
- **Retained committed test history:** The Step 6A follow-up completed normal-browser rental start, return and payment. CUSTOMER 1981, VEHICLE 3981, RENTAL 7016 and PAYMENT 8018 remain as clearly marked fictional records because genuine rental/payment history is protected from deletion and the master records are referenced. Current counts are 11/11/10/10/11/10/11/11 in schema order. The 81 original seed rows still match exactly. See `acceptance-test-results.md` and `evidence/step6a-committed-final-audit.log`. The earlier rollback-only rehearsal remains valid historical evidence; it is no longer the only browser workflow evidence.
- **Lost write response:** A timeout or disconnection can occur after Oracle commits. The UI warns that the result is uncertain and directs the operator to refresh/search before retrying. There is no idempotency key or automatic deduplication across separate retries. In-flight repeated clicks/Enter on one form produced one request in the tested scenario.
- **Pagination:** Lists support search and a bounded limit (up to 100) but no offset or full-page pagination; the UI says so. The fictional sample is well below this limit.
- **Submission material:** The final report, handwritten individual analysis and viva package belong to Step 6B or instructor preparation and were intentionally not generated in Step 6A.
